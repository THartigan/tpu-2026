# Improvement 2: Correctness-Focused Reward Tuning

This change shifts reward pressure from formatting toward answer correctness after the model has learned the output template. Format rewards keep their full value for the first 500 train steps, then linearly decay over the next 500 steps to a final 25% scale so valid-looking but wrong answers are less over-rewarded without an abrupt reward change. Numeric correctness is less brittle through shared parsing for commas, currency signs, trailing punctuation, percentages, fractions, and whitespace, while exact answer rewards are increased to make solving the problem more valuable than merely matching the template. A separate long-output penalty discourages completions that approach the generation cap, and KL regularization is relaxed to `BETA = 0.10` because the previous run showed low KL and zero policy-gradient clipping.

Training now uses the full shuffled GSM8K train split except for a 50-question holdout used for lightweight during-training eval. That eval runs every 250 steps, while standalone `evaluate.py` uses the full Kaggle test split. Training also has a default 5-hour wall-time cap for graceful exits, and it force-saves a checkpoint whenever eval `check_answer` reaches a new high unless `--no-save-best-eval-check-answer` is passed. The current best checkpoint is mirrored to `CKPT_DIR/<experiment>/best_check_answer`, outside normal checkpoint retention, and is overwritten only by a later better checkpoint.
